# Аудит XKeen Happ USB (исходная сборка от 26.10.2026)

Проверено: все скрипты (`install-xkeen-sub.sh`, `xkeen-sub`, `xkeen-rci-setup`, `S98/S99`, `api.cgi`, `index.html`, сборщик флешки, deploy-скрипты), архив флешки `aarch64-installer.tar.gz` (вложенные файлы совпадают с исходниками). Поведение сверено с исходным кодом XKeen 2.1 (jameszeroX), архивами Entware и набором пакетов Entware.

## Критично (исправлено)

| # | Проблема | Последствие |
|---|---|---|
| 1 | Панель без пароля, API отвечает с `Access-Control-Allow-Origin: *` | любая веб-страница, открытая в домашней сети, читала ссылку подписки и меняла настройки |
| 2 | Поле `update_cron` из панели без проверки записывалось в crontab | выполнение любой команды от root; вместе с п. 1 — захват роутера через браузер |
| 3 | В BusyBox из Entware нет `httpd`, а `python3`/`lighttpd` не ставились | на чистом роутере панель не запускалась вообще |
| 4 | Установщик по SSH запускал интерактивный установщик XKeen с выводом в `/dev/null` | установка зависала на невидимых вопросах |

## Серьёзно (исправлено)

- Подписка и XKeen скачивались с `curl -k` (без проверки сертификата) — возможна подмена серверов и кода.
- Имена серверов, адреса и SNI из подписки вставлялись в страницу через `innerHTML` — подписка могла выполнить скрипт в панели.
- Флешка: автонастройка ждала ручной перезагрузки; при любом сбое (нет интернета) удаляла себя и больше не запускалась; был только архив aarch64.
- Ссылки `file://` принимались как подписка (чтение локальных файлов роутера).
- Модель «Netcraze Ultra» и версия ОС «5.1» были зашиты в заголовки подписки; в панели всегда горело «Подключено • Xray активен» и демо-цифры трафика.
- Домашняя сеть переводилась в политику XKeen, даже если у неё была своя; DNS добавлялся поверх настроенного пользователем.
- В журнал (и в панель) писалась полная ссылка подписки с токеном.

## Найдено независимым ревью после переделки (исправлено)

- Новый конфиг Xray применялся без проверки — одна битая запись в подписке оставляла дом без интернета. Теперь сначала `xray run -test`, при ошибке остаётся прежний конфиг.
- Без `flock` блокировки не было, временные файлы общие — одновременная запись cron и панели могла обнулить настройки. Теперь замок через каталог и уникальные временные файлы; повреждённый `config.json` сохраняется копией.
- Адреса серверов из подписки шли в `curl` без проверки (запросы на `127.0.0.1:79` и перебор подсети). Теперь адрес и порт проверяются, `curl -g`.
- Первый пароль мог задать любой в сети, пока владелец не открыл панель. Теперь окно 24 ч после установки или явное разрешение по SSH.
- Управляющие символы в имени сервера ломали разбор всей подписки.

## Проверка на железе

Версия 1.1.0 проверена на Netcraze Ultra (NC-1812, KeeneticOS 5.1.8, aarch64) с подпиской из 10 серверов: установка по SSH поверх рабочего XKeen 2.0, обновление XKeen до 2.1 из панели, выбор по скорости, kill switch, устройства, откат конфига. Найденные на роутере ошибки исправлены (см. CHANGELOG 1.1.0).

Ещё не проверено на железе: установка с флешки (Entware + автонастройка), роутеры mipsel и mips, Telegram-уведомления.
